# FIQA-CBP

Research implementation of **Certified Behavioral Partitions (CBP)** for
one-sided, evidence-aware Face Image Quality Assessment (FIQA) and face
verification.

This repository implements the current merged CBP proposal as an experimental
system rather than treating the proposal as an already validated method. The
core pipeline keeps a frozen face-recognition matcher, learns a shared
image-level behavioral partition, solves context-specific evidence-aware gating
policies, trains an inductive router, refits statistics on the deployed router,
and performs independent identity-level certification.

## Scientific status

- The code is designed to **test** the CBP hypotheses; it does not establish
  them by construction.
- The main protocol is **one-sided probe filtering**. Gallery/reference images
  are not gated by the core method.
- The independent statistical unit is an **identity cluster**, not an image
  pair. Pair bootstrap and pair-count-as-sample-size are deliberately avoided.
- The default FR backbone is external and frozen. Supply a reproducible NPZ
  embedding cache generated by a declared checkpoint and preprocessing
  protocol.
- The finite-state operator is exact on the constructed observable state space.
  Its relationship to raw images is an approximation that must be measured.
- A certificate may correctly return `INSUFFICIENT_EVIDENCE`. Such failures are
  part of the result and must not be removed from reporting.

## Implemented components

1. **Exact finite-state CBP operators**
   - weighted adjoint;
   - first-order influence operator `A`;
   - degenerate operator `V`;
   - identity-budget-dependent `Q_n`;
   - PSD and exact-enumeration tests.

2. **Identity-cluster moment estimation**
   - identity-balanced coverage and genuine-yield moments;
   - symmetrized directional one-sided impostor kernel;
   - plug-in Hoeffding decomposition;
   - state/cell covariance matrices for a planned identity budget.

3. **Representations and controls**
   - CBP evidence-aware hard cells;
   - mean-only cells with matched `K`;
   - embedding k-means;
   - random partitions;
   - dense state policy;
   - shared continuous low-rank policy;
   - scalar common-ranking and context-conditioned ranking policies;
   - `{hard, continuous, dense} x {mean-risk, evidence-aware}` factorial report.

4. **Policy fitting**
   - the constrained objective

     `max u^T beta`

     subject to

     `ell^T beta + rho * sqrt(beta^T B beta) + reserve <= 0`,

     `coverage_low <= p^T beta <= coverage_high`,

     and `0 <= beta <= 1`;
   - CVXPY SOCP solve with a checked SciPy fallback;
   - context-specific decoded profile and dual-based quality score.

5. **Router and deployment**
   - shared single-image MLP router;
   - identity-disjoint validation and early stopping;
   - policy-disagreement diagnostics;
   - mandatory deployed-map moment refit;
   - locked inference artifacts.

6. **Certification and evaluation**
   - independent identity-level calibration;
   - conservative bounded-mean and order-2 U-statistic bounds;
   - per-context error-budget allocation;
   - identity-balanced test metrics;
   - identity-cluster paired resampling utilities;
   - cross-domain evaluation and target-domain recertification scripts.

7. **Synthetic validation**
   - hard-cosine cycle counterexample;
   - exact-vs-Monte-Carlo U-statistic variance;
   - synthetic face-like embedding generator;
   - optional end-to-end integration smoke test.

## Input NPZ format

The canonical experiment consumes an `EmbeddingTable` NPZ containing:

```text
embeddings      float32 [N, D]
identity_ids    string  [N]
sample_ids      string  [N]
image_paths     string  [N]   optional
split_labels    string  [N]   optional: repr/fit/dev/cal/test
```

If `split_labels` is absent, the code creates deterministic identity-disjoint
splits. If present, identity disjointness is checked.

Every retained identity should have at least two captures. Singleton identities
are removed by the canonical runner according to
`min_captures_per_identity`.

## Recommended repository and storage workflow

Keep **source code** in this GitHub repository and keep large/restricted artifacts
outside Git:

- GitHub: source, configs, tests, docs, notebooks;
- Google Drive or equivalent storage: raw datasets, embedding caches, checkpoints
  and experiment outputs;
- Colab local disk: temporary cloned source and extracted image files for fast I/O.

For the current CFP pilot, use `colab/CBP_CFP_Core_Feasibility_Pilot.ipynb`.
The notebook clones this repository, reads the CFP ZIP from Drive, stores
embeddings/results back to Drive, and prints the exact Git commit SHA used.

Do not commit face datasets, embeddings, model checkpoints, tokens, or generated
experiment artifacts to this repository.

## Real-face workflow

### 1. Build a manifest

Expected dataset layout:

```text
dataset_root/
├── identity_0001/
│   ├── image_1.jpg
│   └── image_2.jpg
└── identity_0002/
    └── ...
```

```bash
python scripts/build_manifest.py \
  --root D:\datasets\faces \
  --output data/manifest.csv
```

### 2. Extract frozen embeddings

```bash
python scripts/extract_embeddings.py \
  --manifest data/manifest.csv \
  --output data/arcface_embeddings.npz \
  --model buffalo_l \
  --provider CUDAExecutionProvider
```

Do not mix checkpoints or preprocessing protocols within one run.

### 3. Run a pilot

Edit `configs/pilot.yaml`, then:

```bash
python scripts/run_full_experiment.py --config configs/pilot.yaml
```

### 4. Run the primary experiment

After E0 and pilot gates have been inspected:

```bash
python scripts/run_full_experiment.py --config configs/full.yaml
```

Run at least two frozen FR checkpoints with the same declared split manifest,
operating contexts and tuning budget. Compare their reports rather than pooling
seeds/checkpoints as if they were independent identities.

## Identity split discipline

The canonical data flow is:

```text
D_repr  construct observable states and teacher partition candidates
D_fit   refit p, u, ell, B and solve policies
D_dev   select frozen candidates and tune router/representation settings
D_cal   independent certificate only
D_test  final locked evaluation only
```

No router, partition, threshold, context, candidate or hyperparameter may be
changed after calibration results are inspected. If such a change is required,
use new independent calibration identities or restart the protocol.

## Outputs

A run directory contains:

```text
outputs/<run>/
├── split_manifest.csv
├── report.json
└── artifact/
    ├── router.pt
    ├── policy.json
    └── state_space.npz
```

`report.json` includes:

- resolved configuration and package versions;
- SHA-256 hashes of inputs;
- identity counts per split;
- threshold diagnostics;
- E1 held-out phenomenon tests;
- candidate and projection diagnostics;
- scalar/partition/continuous controls;
- factorial design results;
- deployed-router refit;
- calibration certificates including failures;
- frozen test metrics;
- paired identity-influence multiplier-bootstrap comparisons against predeclared controls;
- Gates A-D.

The `artifact` directory is the locked inference package. Its certificate is
valid only for the declared population/context/protocol and does not transfer
automatically across domains, matchers or gallery composition.

## Interpretation of the gates

- **Gate A — phenomenon:** held-out mean-matched states retain measurable
  evidence differences after declared controls.
- **Gate B — decision relevance:** the deployed router is feasible and meets a
  predeclared genuine-yield margin against the matched-`K` mean-only partition
  (or reaches feasibility when that control cannot); lower variance alone is
  insufficient.
- **Gate C — strong baseline:** hard CBP is not below every feasible dense or
  shared-continuous same-objective comparator. Failure narrows the hard-cell
  claim; it does not automatically refute the evidence-preservation principle.
- **Gate D — nonvacuity:** independent calibration yields useful certified
  coverage/yield. A correct but always-vacuous bound is not a practical result.

See `docs/EXPERIMENT_PROTOCOL.md` for the full E0-E9 program.

## Non-claims

This implementation does **not** imply:

- that hard cells are universally optimal;
- that more image pairs create more independent evidence;
- that a synthetic result proves a real-face phenomenon;
- that a fitted `Q_n` objective is itself a valid confidence bound;
- that a certificate transfers to another domain or matcher;
- that router classification accuracy is sufficient;
- that a benchmark gain establishes theorem novelty;
- that the current proposal is accepted, statistically significant or SOTA.

## Primary implementation assumptions

See `docs/IMPLEMENTATION_ASSUMPTIONS.md`. Important assumptions include the
finite-state approximation, frozen matcher, declared context grid,
identity-balanced population weighting, complete identity-pair fitting in the
primary experiment and independent calibration.
